Isolating GPU vs. Middleware Bottlenecks in Multi-Robot Simulation

Summer 2026 · Robotics Simulation · Multi-Robot Systems

As GPU-accelerated simulators scale to multi-robot fleets, it becomes unclear whether performance bottlenecks originate from GPU compute or from the ROS 2/DDS middleware layer — a distinction that directly affects how teams provision hardware and design fleets. I designed and ran an empirical benchmark in NVIDIA Isaac Sim to isolate these two sources of bottleneck across fleet size and sensor load, building the full instrumentation pipeline from scratch.

  • Designed a controlled sweep varying fleet size (1-3 robots) and sensor load (LiDAR, +IMU, +camera) on a ROS 2 Humble / Nav2 navigation stack
  • Built a Python/Bash instrumentation pipeline deriving real-time factor, per-topic DDS bandwidth/rate/jitter, and Nav2 deadline-miss rate directly from recorded simulation data
  • Implemented process-level CPU/memory attribution across the simulator, navigation stack, and bridge processes
  • Identified a quantified scalability breakpoint: real-time factor collapsed to 0.079 with GPU utilization pinned near 100% at maximum fleet size and sensor load, directly linking middleware-level load to degraded navigation-stack outcomes

FPGA-Accelerated Map Inflation for Robotics

Spring 2026 · FPGA Acceleration · Robotics Navigation

Designed a specialized hardware accelerator to speed up map inflation, a key operation in robotic navigation for collision avoidance in dynamic environments. The project focused on achieving deterministic, low-latency performance for safe human-robot collaboration.

  • Designed a Sparse Patch Systolic Array (SPSA) architecture for deterministic map inflation
  • Built a hybrid pipeline combining software-based detection with hardware-based inflation logic
  • Implemented and optimized the RTL using AMD Vivado and Vitis
  • Mapped multiplication operations to DSP primitives to reduce LUT utilization
  • Achieved high-frequency and low-power implementation on Spartan-7 FPGA

Designing a Zero Trust Access-Control Specification for a Multi-Agent Banking Platform

2026 · AI Security Architecture · Agentic Banking Systems

Banks adopting agentic AI face a control problem traditional security models don't cover: the agent making a decision can be manipulated through language, not just exploited through a code bug. As part of a team project analyzing how to secure a bank's multi-agent platform, I was responsible for the Zero Trust specification — formally defining every agent, tool, API, and data resource in the system, and the exact rules governing what each is allowed to do. This became the foundational artifact used to build enforcement tooling.

  • "Defined a complete Zero Trust specification modeling 29 agents across 3 business domains, 28 tools, 9 APIs, and 6 data resources, including their full interaction graph, trust boundaries, and identity model
  • Wrote 24 explicit access-control rules — session validation, prompt-injection blocking, cross-domain routing restrictions, financial-write authorization — structured around a subject/resource/action/condition/decision format consistent with the XACML standard and NIST SP 800-207 Zero Trust Architecture
  • Designed a risk-tiered enforcement model, scoring every action 1-5 by potential impact, so real-time authorization is reserved for the highest-risk actions (financial writes, ledger updates) while routine reads carry lighter checks
  • This specification was adopted as the baseline for the team's downstream Zero Trust enforcement build-out — automated resource discovery, enforcement-point generation, and a policy decision engine — later verified against real transactions on the banking backend
  • Built a technical presentation translating the raw specification into plain-language decision tables and system diagrams for internal review, making the security model legible to reviewers without a security background
